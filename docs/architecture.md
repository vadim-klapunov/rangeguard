# Архитектура RangeGuard

## Подключение расширения к VS Code

VS Code предоставляет API для добавления команд, обработки
документов и отображения диагностических сообщений.

Код RangeGuard выполняется в Extension Host — среде выполнения
расширений, отделённой от интерфейса редактора.

Файл package.json является манифестом расширения. Он содержит:

- название и версию;
- требуемую версию VS Code;
- путь к основному JavaScript-файлу;
- описание языка ranges и расширения файлов .ranges;
- список доступных команд;
- события активации.

При активации VS Code загружает src/extension.js и вызывает
экспортированную функцию activate(context).

Функция activate регистрирует команды, обработчики событий
и коллекцию диагностических сообщений.

Созданные ресурсы добавляются в context.subscriptions,
чтобы VS Code мог освободить их при деактивации расширения.

## Модули проекта

### src/extension.js

Отвечает за взаимодействие с редактором:

- получает содержимое документа;
- запускает анализатор;
- преобразует найденные проблемы в Diagnostic;
- обновляет подчёркивания и панель «Проблемы»;
- запрашивает число для проверки;
- показывает подходящие правила;
- формирует и открывает Markdown-отчёт.

Проверка запускается при открытии и сохранении документа
или по команде пользователя.

При активации также проверяются уже открытые документы.
При закрытии документа его диагностические сообщения удаляются.

### src/analyzer.js

Содержит логику обработки диапазонов и не зависит от API VS Code.

Основные функции:

- analyze(text) — разбирает документ и проверяет диапазоны;
- validNumber(value) — проверяет допустимость числа;
- segment(min, max) — формирует текстовое представление участка;
- findMatchingRules(result, value) — находит правила для числа.

Независимость анализатора от редактора позволяет проверять
его отдельно с помощью Node.js.

## Структуры данных

Общая область хранится в объекте с полями:

- min — минимальное включённое значение;
- max — максимальное включённое значение;
- line — номер строки в исходном документе, начиная с нуля.

Правила хранятся в массиве объектов. Каждый объект содержит:

- name — название правила;
- min — минимальное включённое целое число;
- max — максимальное включённое целое число;
- line — номер строки правила, начиная с нуля.

Множество Set используется для обнаружения повторяющихся названий.

Проблемы хранятся в массиве issues. Каждая проблема содержит
номер строки line и сообщение message.

Поле valid в результате анализа показывает, можно ли выполнять
проверку покрытия и пересечений. Оно не означает отсутствие
всех проблем: при valid = true могут существовать пропуски,
пересечения и выходы за общую область.

## Алгоритм проверки

1. Текст разделяется на строки.
2. Пустые строки и комментарии пропускаются.
3. Распознаются общая область и правила.
4. Проверяются формат, числа, названия и порядок границ.
5. Открытые границы преобразуются во включённые целые границы:
   (a, b) становится [a + 1, b - 1].
6. Проверяется, не стал ли диапазон пустым.
7. При блокирующих ошибках дальнейший анализ прекращается.
8. Проверяется выход правил за общую область.
9. Для анализа покрытия правила обрезаются по общей области.
10. Диапазоны сортируются по левой, затем по правой границе.
11. Проверяются пересечения пар диапазонов.
12. Последовательным проходом находятся непокрытые участки.

Каждое пересечение отмечается на обеих участвующих строках.
Пропуски привязываются к строке domain.

Алгоритм сравнивает границы и не перебирает все числа области.

## Сложность

Пусть n — количество правил, а L — длина документа.

Разбор текста требует O(L) времени.
Сортировка диапазонов требует O(n log n).
Поиск пересечений в худшем случае требует O(n²).
Поиск пропусков после сортировки требует O(n).
Поиск правил для одного значения требует O(n).

Общая временная сложность анализа в худшем случае:
O(L + n²).

Массив диагностических сообщений может занимать O(n²) памяти,
если пересекается большое количество пар правил.

## Обработка результатов

Для каждой проблемы создаётся объект Diagnostic
с описанием, диапазоном строки и уровнем Error.

Коллекция диагностик обновляется для конкретного документа.
Благодаря этому после исправления и сохранения файла
старые сообщения заменяются актуальными.

При экспорте создаётся новый несохранённый Markdown-документ.
Пользователь самостоятельно выбирает путь его сохранения.

## Ограничения

Расширение обрабатывает целочисленные правила в формате .ranges.
Оно не анализирует условия в исходном коде других языков.

Правила не имеют приоритетов.
Пересечения считаются проблемой, даже если они задуманы автором.

Диагностика обновляется при открытии, сохранении
и ручном запуске проверки, а не после каждого нажатия клавиши.
