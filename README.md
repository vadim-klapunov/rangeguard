# RangeGuard

Расширение для Visual Studio Code, которое проверяет числовые
диапазоны: находит пропуски, пересечения и ошибки границ.

Автор: Клапунов Вадим Владимирович  
Группа: М3117  
Лабораторная работа №3 по дисциплине
«Инструментальные средства разработки ПО».

## Назначение

RangeGuard помогает проверять правила распределения целых чисел
по категориям: тарифы доставки, скидки, игровые уровни,
пороги мониторинга и другие числовые условия.

Каждое число заданной области должно относиться ровно к одному
правилу. Порядок правил не задаёт приоритет.

## Возможности

- Проверка формата файла и допустимости чисел.
- Обнаружение повторяющихся названий правил.
- Обнаружение обратных и пустых диапазонов.
- Проверка выхода диапазонов за общую область.
- Поиск пропусков и пересечений внутри общей области.
- Подчёркивание проблемных строк и сообщения в панели «Проблемы».
- Автоматическая проверка при открытии и сохранении файла.
- Ручной запуск проверки.
- Поиск правил для введённого числа.
- Создание отчёта в Markdown.

## Запуск расширения из исходников

1. Откройте папку проекта в Visual Studio Code.
2. Нажмите F5 и при необходимости выберите «Запустить RangeGuard».
3. В открывшемся окне Extension Development Host откройте
   файл examples/delivery.ranges.
4. Откройте панель «Проблемы» сочетанием Ctrl+Shift+M.
5. Для выполнения команд нажмите Ctrl+Shift+P и введите RangeGuard.

При работе через WSL открывайте папку проекта в режиме WSL.

## Формат файлов

Расширение работает с файлами .ranges.

Пример:

```text
# Вес посылки в граммах
domain: 0..10000

Малая посылка: [0, 1000)
Средняя посылка: [1000, 5000)
Большая посылка: [5000, 10000]
```

Первая содержательная строка задаёт область domain.
Обе границы общей области включены.

Каждое правило записывается на отдельной строке:

```text
Название: [левая граница, правая граница)
```

Обозначения:

- `[` — включить левую границу.
- `(` — исключить левую границу.
- `]` — включить правую границу.
- `)` — исключить правую границу.

Пустые строки и строки, начинающиеся с #, игнорируются.
Названия правил должны быть непустыми и уникальными.
Двоеточие используется как разделитель названия и диапазона.

## Ограничения

- Поддерживаются только целые числа от -1000000000 до 1000000000.
- Отрицательные значения разрешены.
- Дробные числа и бесконечные границы не поддерживаются.
- Требуется ровно одна область domain и хотя бы одно правило.
- Анализируется формат .ranges, а не произвольный программный код.

Для величин с дробной частью можно использовать целые значения
в меньших единицах: копейки вместо рублей, граммы вместо килограммов.

Диапазон [0, 5) содержит числа от 0 до 4.
Диапазон [5, 5] содержит одно число.
Диапазон (5, 6) не содержит целых чисел и считается ошибочным.

## Команды

### RangeGuard: Проверить диапазоны

Проверяет активный файл .ranges и обновляет сообщения
в панели «Проблемы».

При ошибках формата, обратных или пустых диапазонах
анализ покрытия и пересечений откладывается до исправления.

Выход диапазона за область отмечается отдельно.
Покрытие и пересечения проверяются внутри области domain.

Одно пересечение создаёт два сообщения:
по одному для каждой участвующей строки.

### RangeGuard: Проверить значение

Предлагает ввести целое число и показывает подходящие правила.

Возможные результаты:

- Одно правило — значение относится к одной категории.
- Несколько правил — значение находится в пересечении.
- Нет правил — значение находится в пропуске.
- Вне domain — значение находится за пределами общей области.

Дробный и некорректный ввод отклоняются.
Нажатие Escape отменяет команду.

### RangeGuard: Экспортировать отчёт

Создаёт новый Markdown-документ с результатами проверки,
общей областью, распознанными правилами и диагностикой.

Проверяется текущее содержимое редактора, включая
несохранённые изменения.

В отчёте границы правил приведены к включённым целым значениям.
Дата записывается в формате ISO 8601 в UTC.

Для сохранения отчёта нажмите Ctrl+S и укажите имя файла .md.

## Проверка

Проведены 12 автоматических проверок анализатора:

1. Отрицательные числа и правильное покрытие.
2. Пропуск нескольких чисел.
3. Вложенный диапазон.
4. Пустой диапазон.
5. Перепутанные границы.
6. Выход за общую область.
7. Повтор названия.
8. Неправильный формат.
9. Отсутствие domain.
10. Отсутствие правил.
11. Диапазон из одного числа.
12. Поиск значения в пересечении и пропуске.

Результат: 12 из 12 проверок пройдены.

Вручную в VS Code проверены диагностика, обновление после
сохранения, поиск значений, отклонение дробного ввода,
выход за общую область и создание Markdown-отчёта.
